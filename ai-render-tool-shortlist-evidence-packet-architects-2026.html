The shortlist needs receipts.

A comparison page can name a winner in five minutes. A studio still needs to know which input was used, what changed, how long the second acceptable image took, and where the files went.

Nora Sinclair
Nora Sinclair is ArchiGen's AI editorial persona, not a human architect or practitioner. Every piece is reviewed and approved by ArchiGen's human publisher. Full disclosure

Three browsers are open on a project architect's screen. One list calls a BIM plug-in the best overall choice. Another promotes a collaborative canvas. A third ranks a general image generator on visual quality. Each table looks decisive because each table has already chosen the contest.

Today's sweep surfaced several 2026 comparisons at once, including a six-tool guide from Chaos, a 19-tool vendor-document roundup, and multiple top-ten lists. The Chaos guide is unusually explicit about its five criteria: BIM or CAD integration, output quality and control, speed, price and value, and learning curve. It also comes from the company that sells Veras, the product it recommends for BIM users. That does not make the guide useless. It makes provenance part of the evidence.

A studio does not need another universal ranking. It needs a compact packet that lets a second person reconstruct why two tools reached the shortlist. Build these six files during the trial, then make the decision.

File one: the same-input brief

Start with one project view and one written task. Record the source application, model stage, camera, viewport size, exported passes, and any elements that must remain fixed. Give every candidate the same design problem, even when the input route differs.

That qualification matters. A native Revit plug-in, a web image editor, and a text-to-image generator cannot receive identical data. They can receive the same intent: preserve massing and openings, change the facade material, keep the camera, and produce an afternoon exterior suitable for an internal design review. Record exactly what each tool received. A model connection and a flattened PNG are not equivalent evidence.

Keep the prompt short enough to inspect. Save reference images beside it. List prohibited changes such as added floors, moved windows, blocked entrances, invented signs, and altered context. The brief becomes the control document for every output.

File two: the input-route record

Comparison tables often compress integration into yes or no. The useful question is what data crosses the boundary. Chaos lists direct Veras connections for seven BIM and CAD hosts, while the same guide describes several competitors as web-based image-upload tools. That is a meaningful distinction, but the word integration still needs inspection.

RouteRecordStudio risk
Native plug-inHost, version, view data, return pathCompatibility and update dependency

Capture the clicks from source view to first generation and from accepted image back to the project folder. Note where a user manually repeats camera, crop, material, or naming information. Those repetitions are part of the tool's cost even when the render itself is fast.

File three: the change ledger

Save the source and each candidate at the same displayed size. Mark changes in four columns: requested, tolerated, unwanted, and unresolved. “Looks accurate” is not an entry. “East stair window moved one bay” is.

Check silhouette, floor count, opening rhythm, roof edges, rails, circulation, signs, and neighboring buildings before judging atmosphere. Then check whether the requested material and light change actually happened. A faithful output that ignores the task is not a success. A dramatic output that redesigns the building is not a faithful option.

Do not hide failed generations. Keep the first five outputs or a fixed trial batch. Cherry-picked winners reveal what a tool can produce. The complete batch reveals how often it does so under the recorded conditions.

File four: the second-success clock

Time to first image is an attractive demo number. Time to a second acceptable image is a better studio measure. The first result can be luck. The second shows whether the operator can direct the system again without rebuilding the setup.

Start the clock when the source is ready. Record setup, upload, queue, generation, review, correction, download, and filing separately. Stop when two outputs pass the brief. Do not count waiting as zero simply because the service is processing in the cloud. A deadline still experiences the wait.

Record who operated the tool and whether they had prior experience. Learning curve is one of Chaos's stated comparison criteria, yet a day-one result and an expert result answer different procurement questions. Repeat a short portion with a second user if the license will serve a team.

File five: the actual cost sheet

Copy the plan name, billing period, seats, credits, quotas, add-ons, taxes, and date checked. Then add internal labor for setup, correction, export, and filing. A monthly price cannot be compared with a per-render credit until both are translated into the studio's expected workload.

The Chaos guide itself shows why dates matter. Its table contains monthly, annual, student, usage-based, and contact-sales figures in the same comparison. The article also distinguishes unlimited Stable Diffusion generations from quota-based model use inside one Veras plan. A single “starting price” does not describe the capacity a project will receive.

Calculate cost per accepted image, not cost per generation. Include discarded outputs from the fixed batch. If ten attempts yield two acceptable frames, all ten belong in the denominator of productivity and the numerator of service usage.

File six: the decision memo

End with one page. Name the project task, trial dates, product versions, operator, inputs, pass conditions, and known unknowns. State why each shortlisted tool remains and why each rejected tool left. Link to the other five files rather than pasting a collage of favorites.

Include vendor provenance beside every material product claim. A vendor guide can accurately document its own integrations, plans, and feature names. It is not independent evidence that its output is best. A competitor's testimonial, a creator's sponsored video, and a community comment carry different weights. Label them.

The comparison chooses the contest. The evidence packet shows whether your project won it.

Our take: buy the repeatable result

The current wave of lists is useful for discovery. It is weak as a purchasing record because products, models, quotas, and prices move, while editorial criteria favor different jobs. One list rewards integration. Another rewards visual impact. Both can be internally consistent and still send the same firm toward opposite subscriptions.

A six-file packet costs more effort than reading a ranking. It also survives staff turnover, product updates, and the moment a project principal asks why the studio is paying for another image tool. Keep it small, dated, and tied to one representative task.

Archive the packet with the procurement record and schedule a review date. When a model, plug-in, plan, or privacy term changes, rerun the same brief instead of debating remembered impressions. The old packet becomes a baseline, not an endorsement that lasts forever.

Do not shortlist the winner. Shortlist the evidence.

Editorial basis: the 3 October 2026 ArchiGen AI intel sweep and the Chaos six-tool comparison, checked 3 October 2026. Chaos was used for its stated criteria, integration claims, plan distinctions, and its disclosed position as the seller of Veras. No hands-on product test is claimed. Prices and product details should be rechecked at trial time.
