A ComfyUI workflow for architectural exteriors

For architectural exteriors in ComfyUI, start with a depth-guided structure pass, then use img2img to study materials, FLUX.1 Fill for masked surroundings, and a separate lighting variation. Use compatible weights and review geometry between stages. This source-led guide links the public examples that supply each model-specific graph.

Source-led guide · Revised 5 October 2026

Which ComfyUI workflow fits architectural exteriors?

Choose by the source image and the change required. Use depth guidance when the input defines the intended massing, a masked edit when a region needs replacing, or an image adapter when the task is a reference variation. BFL documents separate structural models, a Fill model for image regions and a Redux adapter for image variations. A longer node graph is not a selection criterion.

Work through geometry, materials, site context, then lighting. Treat these as review stages: keep an accepted output before starting the next operation. This order is an editorial recommendation based on the documented operations. Keep the model, encoders, VAE and conditioning components compatible with the chosen example; the FLUX and SDXL model-choice guide explains the separate routes.

1. Establish the structure

FLUX.1 Depth [dev] generates images guided by a depth map. Start with the intended camera and massing. Where the source model can export depth, use that map as the proposed structural input and inspect it before generation. This recommendation follows the model's conditioning mechanism; it is not a claim that every opening will survive unchanged.

If the input is only a rendered image, MiDaS estimates depth from that image. An estimate and a model export are different sources of information. The auxiliary preprocessor pack creates hint images, including depth and edges; it does not replace the weights that use those hints.

Import the corresponding ComfyUI FLUX example, load its required files and supply the source input. Use the example's compatible components before adding custom nodes. BFL's full Depth model and its Depth LoRA are distinct options; the LoRA route requires FLUX.1 [dev]. Neither is an SDXL ControlNet.

Save a candidate and compare its silhouette and openings with the source. Make that comparison a decision point before changing surfaces. The stage-checkpoint guide expands this review method; it supplies no measured success rate for the workflow described here.

2. Change materials from an accepted image

ComfyUI's img2img documentation describes loading an image, encoding it with a VAE and sampling that latent with reduced denoise. Lower denoise adds less noise and generally changes less of the input. That explains the control; it does not establish one correct value for concrete, glazing or brick.

Use the accepted structural image as the starting point for a material study. “Board-formed concrete, pale grey surface” is a prompt example, not a tested recipe. If the requested change is confined to a region, choose a compatible masked-edit workflow rather than assuming a full-image instruction will protect everything else. Review the boundary as well as the material. A convincing texture can still belong to the wrong wall.

Sampler values belong to the selected model example. The FLUX fp8 checkpoint example, for instance, specifies Load Checkpoint with CFG 1.0. Do not copy an SDXL sampler recipe into it. ComfyUI also warns that fp8 can reduce quality; it recommends the full 16-bit version when resources permit. This is not a hardware capacity guarantee.

3. Choose the operation for site context

For a local edit, FLUX.1 Fill [dev] accepts an existing image and a mask to fill a region according to a text description. The ComfyUI Fill example includes access to MaskEditor from Load Image. Mark the region intended to change, run the documented example and compare the edited edge with the source. A mask is an instruction to the workflow, not evidence that the resulting context is geographically correct.

For an image-reference variation, Redux is a FLUX.1 image adapter. Treat it as a different operation from filling a selected region. The reference image supplies visual information; it does not verify site conditions. Use a reference you have permission to use and keep its origin with the output.

The IP-Adapter model card places ip-adapter-plus_sdxl_vit-h in its SDXL family. That adapter is not the FLUX Redux component. A matching-sounding filename cannot make those families interchangeable.

4. Review lighting as another image change

For a lighting variation, return to the accepted context image and use a compatible img2img workflow. “Overcast daylight” and “warm evening light” are illustrative prompts. The documented denoise control governs how much noise enters the starting image; it does not promise a lighting-only edit.

Compare the candidate with the same baseline before accepting another variant. Check whether the material request still reads correctly and whether openings changed. Keep the original control inputs with the workflow; the second-pass guide discusses their use in later passes. No fixed render time or universal denoise schedule is claimed here.

Keep the workflow reproducible

ComfyUI-Manager can save installation snapshots, but its documentation says snapshot support is incomplete for custom nodes not managed by Git. Record versions and required files alongside the workflow; do not treat a saved graph as a complete environment backup.

Custom packs are optional until a specific graph needs them. Advanced-ControlNet exposes control strength and sampling-time scheduling. Those controls are not a mandate to stop conditioning at one particular percentage, and the pack is not required simply because this guide has “advanced” in its URL.

For enlargement, Ultimate SD Upscale documents tiled img2img inside ComfyUI. Inspect it as another generative edit. There is no basis here for a claim that an external upscaler is required for architectural work.

Save the source image, model names and each accepted stage. The next pass should have a reason to exist.
